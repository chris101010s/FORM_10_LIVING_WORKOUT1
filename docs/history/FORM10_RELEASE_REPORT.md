# FORM 10.0 — The Living Workout · Release report

**Status: locally tested development candidate, not a verified iOS release.**

## Baseline and decisions

- Directly modified the uploaded `ATHLETE_OS_8_4_FORM_FRESH_START_HOTFIX.zip`, not an invented FORM 10 project. Existing React Native/Expo dependencies and module structure retained. Name and technical version are FORM 10.0 / 10.0.0. Kept the previous Linking TS2345 fix accepting `undefined`.
- Bundle ID `app.athleteos.personal`, SQLite `form-v84-clean.db`, DB schema 8, JSON schema 4, existing encryption/backup keys, HealthKit/Widget optional build and exercise catalog are unchanged. Added optional session metadata to existing payloads; no destructive migration. An 8.4 installation keeps its data. A new installation remains empty. No personal data seeded. No automatic import from older isolated namespaces.
- The updated prompt makes the active workout the priority. No new dependencies added, no new project generated. Existing build runner and optional native-tab compatibility mode retained.

## Implemented in source

1. Timestamp clock: UTC ISO start/creation dates, optional active/paused status, pause accumulation, live header and mini-player, start time, app-state refresh, clock anomaly/long-session recovery and adjustable finish date/time. The existing session ID acts as `sessionId`; no duplicate alias. Historical completed status is optional for old backups. Discard is a confirmed deletion rather than a separately persisted discarded status. Draft status is represented by the existing set drafts, not a separate workout status.
2. Durable edits: existing WAL-backed relational repository, serialized transaction queue, only changed SQL rows written, new session metadata validated and included in backups. Editing current fields/notes immediately queues a write; no dependency on an app-close event. New stable sequence guard rejects replayed set completions, in-flight and short repeated-tap guard at UI. Successful save acknowledgement drives haptics and PR message. Failure retains optimistic state in memory, shows retry rather than forcing the active screen closed. Failure before committing can still lose the latest uncommitted change if the OS kills the app. `lastSavedAt` is the snapshot write-attempt timestamp persisted with the snapshot; the provider's `lastSaved` is the confirmed commit time for the current process. No coalescing of text input yet; the existing full-state validation/diff remains in memory, not a full JSON database rewrite.
3. Active view: fixed header, focus on one exercise, existing licensed/cached thumbnail or placeholder, compact table of completed rows plus next editable row, explicit prior suggestions, direct kg/reps and check button, advanced RIR/RPE and other set types in details, editable historical rows, prior date and e1RM, quick repeat, next exercise action, compact exercise list, menu for name/notes/reorder/swap/remove/block advance, optional plate calculator with blank bar input. Exercise swap retains logged sets under their original exercise IDs; an unlogged draft is discarded only after confirmation when swapping. Quick catalog supports favorites/recent plus existing search, muscle/equipment filters. Superset/giant/circuit retains existing automatic group navigation; straight sets do not automatically jump to the next exercise.
4. Rest clock: independent absolute deadline, pause/resume, +/-15 seconds, skip, manual start using per-exercise prescription; if the whole workout is paused, current rest is preserved as a paused countdown and can be resumed separately. Existing opt-in notifications and haptics remain; delivery still depends on platform permission and actual device scheduling. Existing training formats/segments retained. No background JS execution promised.
5. Finish/recovery: unusual session prompt after four active hours or 12 wall-clock hours, also when backward clock anomaly detected. Finish receipt, native iOS end-time selector, validation that finish cannot precede last saved set, transaction adds history and removes live record, then existing review/comparison/record tickets, optional share. Prior pauses are accumulated, not a timestamped audit trail of each pause; corrected historic finish may only be approximated if it predates a past pause.
6. Paint identity: shared warm-white/blue tokens, flatter edges, fixed header and small paper-like sticker, custom SVG star, 180 ms native-driver slide/fade for exercise change/rows/PR and shared Reduce Motion state. Existing Dark/Paper palettes and opt-in motivational controls remain. UI design is implemented but not visually reviewed on a simulator. Native tab bar remains visible in native mode; custom fallback hides tabs in active training. No fake screenshots.
7. Existing plans, progress, health, backups, custom exercises, settings retained. Shared component styling updated, not a full rebuild of every screen. CI font script updated to attempt Outfit, DM Sans and JetBrains Mono with OFL verification, system fallback. Assets not downloaded here.

## Remaining gaps (not accepted yet)

Native navigation and visual quality must be verified on iPhone. Existing notification permissions and optional entitlements remain unverified. Native date picker integration, React refs and full TypeScript must pass CI before a release is accepted.
- The table intentionally exposes the next editable row rather than simultaneous persistent drafts for every planned future row; no separate persisted scroll offset. A draft per exercise remains supported, not an arbitrary multi-row draft model. No full undo/redo. End-time adjustment via native picker on iOS; Android ISO input fallback. No automatic app-termination event reliance; last uncommitted edits can be lost on forced termination.
- No configurable plate inventory/repetition increment, full alternative rest overlay, full session draft/discarded-state archive, separate normalized SQL draft table or measured performance. Existing kg step settings retained. Existing broad backup validation and SQL row diff can be expensive with very large histories; no measured phone performance. - Some specified new doodle illustrations, rare retro color palette, workout-specific Easter eggs, typography verification and further polish across every non-workout screen are incomplete. Fonts and full 800+ photos require CI network access. No artificial stats or screenshots supplied. Existing optional Apple Watch/HealthKit/Widget limitations inherited from 8.4.
